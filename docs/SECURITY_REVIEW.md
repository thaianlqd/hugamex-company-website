# Security review — local implementation

Reviewed 2026-10-05. This is a code review and local regression report, not a penetration-test certificate. External Google, Supabase, SMTP, HTTPS proxy and production secrets have not been configured or tested.

| Risk | Relevant code | Mitigation | Remaining risk / next validation |
| --- | --- | --- | --- |
| Broken access control / IDOR | `security/Policy`, `BearerFilter`, admin controllers, `MediaController` | Backend role checks on every action; roles/account/session read from DB. Public content is PUBLISHED only; private media requires CMS authorization. USER has no admin access. | Test deployed proxy and dedicated DB runtime grants. |
| Privilege escalation | `AdminUserService`, `Policy` | ADMIN cannot create/manage privileged users or assign roles. SUPER_ADMIN + MFA + authentication within 5 minutes for security changes. Transactional advisory lock and target row lock protect the last active SUPER_ADMIN. Mixed EDITOR/ADMIN cannot bypass MFA. | Operational account recovery must be controlled outside the public API. |
| Authentication failures | `AuthService`, `AuthRequests`, `DevEmailService` | Argon2id, passphrase validation, dummy hash for unknown emails, generic login/reset responses. OTP purpose/account/challenge-bound HMAC; 5 minutes, 5 attempts, 60-second resend. Challenges consumed once. Failed login audit contains no email/password. | SMTP timing/delivery can differ; rate limiting reduces enumeration and brute force but does not prove identical timing. |
| MFA bypass / replay | `MfaService`, `Totp`, `Policy`, `MfaGate` | ADMIN/SUPER_ADMIN mandatory. Configured EDITOR MFA enforced. Encrypted TOTP secret, monotonic accepted counter, 5 attempts/5 minutes. Recovery codes hashed, single use; regeneration invalidates old codes. Reset by another SUPER_ADMIN revokes sessions. | No WebAuthn/passkeys. Securely retain recovery codes and encryption key. |
| CSRF | `SecurityConfig`, `AuthController`, `services/api.ts` | CSRF cookie is HttpOnly; token obtained through same-origin API and sent in `X-CSRF-TOKEN`. Required for refresh/logout/login/OTP/reset and contact. Bearer-only admin/MFA/account endpoints do not authenticate with cookies. | Verify cookie path/SameSite/Secure and real origins under HTTPS. |
| Session fixation / refresh replay | `SessionService`, `JwtService`, `BearerFilter` | Random 32-byte opaque refresh tokens; HMAC digest persisted; rotating family, reuse revokes family. JWT lasts 10 minutes and is bound to a live persisted session. Password/role/status changes and logout revoke sessions. User-row locks serialize creation/refresh/revocation. | Multiple tabs concurrently rotating a cookie can trigger fail-closed reuse detection; sign in again. No absolute maximum family lifetime beyond current 7-day sliding expiry. |
| Token leakage | `AuthProvider`, `services/api.ts`, OAuth success handler | Access/reset tokens only in memory; refresh HttpOnly cookie; OAuth returns cookie + clean redirect, no JWT in query/hash. Logout clears memory/cache. localStorage stores language only. | XSS can act as the logged-in user; CSP and structured rendering remain required. QA credentials stay only in ignored local files. |
| XSS / content injection | `ContentValidation`, `Shared.RichText`, `Seo` | Strict TipTap node/attribute/URL allowlist, bounded document size/depth/node count. Render React elements without raw HTML. JSON-LD escapes `<`. No arbitrary page-builder scripts/styles. | Keep extensions and node renderer aligned when adding editor features. Production CSP must be tested with the exact frontend build. |
| SQL injection | JDBC services, `PageResult` | Bound SQL parameters, static resource/kind allowlists, UUID validation, bounded filters and pagination. RLS migration targets fixed application tables only. | Dynamic SQL additions must preserve the allowlists. |
| Mass assignment | `ContentRequests`, `ContentService.save`, CMS editor | DTO excludes role/owner/publish date; new content is DRAFT, actor comes from security context. Status transition is a separate authorized endpoint. Jackson rejects unknown fields. Editor submits selected editable fields only. | Re-review new DTO properties and all import/bulk endpoints if introduced. |
| File upload abuse | `MediaValidation`, `MediaService`, `PostgresMediaStorage` | MIME + extension + signature validation; JPEG/PNG/WebP ≤5 MB, PDF ≤10 MB; decoded image dimensions bounded; sanitized filename; BYTEA with no OID/@Lob. PDF downloads as attachment + nosniff. | Signature validation is not antivirus or a PDF sanitizer. Malware scanning/sandboxing must be assessed before accepting untrusted high-volume uploads. |
| Media deletion / privacy changes | `MediaService`, `ContentService.media` | Transactional media locks; referenced deletion rejected. Published content cannot use private media or switch its media to private. Metadata edits audited. | A formerly public binary may remain in a browser cache up to 60 seconds; a downloaded copy cannot be revoked. |
| SSRF | Content and media APIs | URLs are validated and rendered as links, never fetched by backend. No arbitrary remote-import endpoint. Dev fixture downloader uses two fixed Pexels URLs and localhost API only. | Any future server-side image fetch, webhook or PDF import needs URL/IP/redirect controls. |
| Rate limiting / abuse | `RateLimiter`, `AuthService`, `MfaService`, `ContactController` | Atomic PostgreSQL counters with persisted rejected attempts. IP and account scopes; contact honeypot; 429 responses. Public content is not globally throttled. | Configure trusted proxy IP handling; do not blindly trust forwarded headers. Schedule bucket/session/challenge retention and assess distributed load. |
| Sensitive data exposure | DTOs, `Errors`, audit, dev mail | No password hash/TOTP secret/OTP raw code in user/public DTOs. Errors omit SQL/stack; logs only error class, no request bodies. Dev mail file permissions 0600/0700; SMTP is prod only. Private media is no-store. | Protect DB backups and application keys separately. Logs/infrastructure analytics must preserve redaction. Contact-message retention needs client approval. |
| Supabase platform exposure | `V4__backend_only_platform_access.sql` | RLS enabled on all 17 app tables, no public policies; explicit table grants revoked from `anon`/`authenticated` if those roles exist. Browser has no Supabase credentials/client. PostgreSQL guest regression verifies default deny even with SELECT grant. | Backend must use an authorized server DB role. Migration owner bypasses RLS locally; production needs a dedicated runtime role/policy and separate migration role. Test Supabase Data API permissions and future tables on staging. |
| Security misconfiguration | Profiles, `AppConfig`, `SecurityConfig`, `GoogleConfig` | Env keys required; production Secure cookies/debug guard, ddl-auto=validate; no wildcard credential CORS. Swagger enabled only dev/test. OAuth uses framework state/OIDC/PKCE; automatic email linking rejected. | Real OAuth callback/state failures and proxy TLS behavior remain untested. Default API CSP is not the frontend CSP. |

## Findings fixed during implementation

- CSRF cookie/header mismatch corrected and verified with the real wire contract plus browser journeys.
- PostgreSQL metadata conversion corrected for publish/unpublish operations.
- Editor no longer sends read-only DTO fields back into the save request.
- Role combinations cannot bypass mandatory MFA; configured EDITOR MFA also enforced.
- Refresh/login/revoke race serialized with user locks; concurrent regression retains revocation.
- Private/referenced media checks retained, with tests for deletion and privacy transitions.
- React 19 title rendering and TipTap destroyed-instance lifecycle corrected through browser tests.
- Frontend tool dependency advisories addressed by removing Lighthouse from application dependencies. `npm audit` on the shipped frontend dependency tree returns zero findings at review time.

## Dependency review limits

Spring Boot was updated within the required 3.x family to 3.5.16. Its managed Security 6.5.11 addresses the SAML output issue; this app does not enable SAML. [Managed versions](https://docs.spring.io/spring-boot/3.5/appendix/dependency-versions/coordinates.html), [SAML advisory](https://spring.io/security/cve-2026-41003/).

Security 6.5.11 is still within the version range of the DPoP cache replay advisory. The application uses its own HS256 bearer/session filter, does not configure `DPoPProofJwtDecoderFactory`, and accepts no DPoP authentication flow. This is an applicability assessment, not a patched-dependency claim. A supported 3.x maintenance/security strategy must be reviewed before production; do not silently change the requested stack to Boot 4. [DPoP advisory](https://spring.io/security/cve-2026-41707/).

Lighthouse 10.1.1 is isolated under ignored `.tools/lighthouse`, not bundled or included in the frontend lockfile. Its tool-only dependency tree has audit advisories, including archive extraction/proxy dependencies. It was used only with already-installed Chromium and a fixed trusted localhost URL, without archive downloading or arbitrary targets. Review/update the measurement tool before using it on untrusted inputs. The isolation does not remove those tool advisories.

No exhaustive automated Java SCA/NVD scan, external penetration test, production header/TLS audit or recovery drill has been executed. No assertion of complete security is made.

RLS behavior follows [PostgreSQL 17 documentation](https://www.postgresql.org/docs/17/ddl-rowsecurity.html) and [Supabase RLS guidance](https://supabase.com/docs/guides/database/postgres/row-level-security); production platform permissions still need verification.
